# Sprint 4B R2 safe release controls

The R2 release is restricted to controlled `development` and `test` environments. Before the E2 migration, the workflow invokes the read-only ownership precondition without changing API ingress or traffic. The precondition runs in one transaction and rolls back; non-zero null-order, null-actor, null-target, or duplicate actor/key counts throw and stop the release. It contains no data repair, backfill, or deletion statements.

After the exact `EnforceCustomerProfileOwnership` migration execution succeeds, the API candidate must pass readiness and live health checks before its 100% traffic assignment is confirmed. Production is explicitly refused and the Sprint 4A D1 image/revision remains the rollback reference. The manifest is a one-shot release control: it is retained only for the development-to-test promotion and must be removed in a follow-up cleanup PR after test acceptance. The EF migration `Down` path is not an operational rollback because its restored E1 key requires non-null `SubjectId`; rollback is instead the retained D1 image.
